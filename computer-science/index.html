Computer Science

Discrete mathematics, graphs, complexity

Computer science, on this site, is the algorithmic and complexity twin of combinatorial graph theory. The same objects — vertices, edges, Eulerian trails, Hamiltonian cycles — appear as data and as decision problems. The definitions live on graph theory; the proofs of existence and uniqueness live in pure mathematics. What follows is the computational vocabulary.

1. Discrete mathematics as the overlap
Discrete mathematics
Finite sets, graphs, counting, logic, and the first algorithms on those objects. It is the shared first language of a computer science degree and of combinatorial research. Both of my degrees are in computer science; the research is graph theory.
A graph as data
In a program a graph is an adjacency list or an adjacency matrix: a finite record of who is joined to whom. In a proof a graph is a pair \( (V,E) \). The drawing can be the same. The question asked of it is not.
A graph as a theorem
“This cubic hypohamiltonian graph admits a dominating cycle” is not a runtime. It is a mathematical claim. Algorithms can search for such a cycle; they do not, by themselves, classify the graphs in which uniqueness occurs. See Research.
2. Algorithms on graphs
Search
Breadth-first and depth-first search walk a graph from a start vertex, visiting each reachable vertex once. They decide connectivity, and they build spanning trees.
Shortest path
Dijkstra's algorithm (non-negative weights) and Bellman–Ford (negative weights allowed, no negative cycle) compute distances. The object is a path of minimum weight, not a cycle through every vertex.
Eulerian circuit
Hierholzer's algorithm finds a closed trail through every edge in linear time, once every degree is even. Euler's theorem is the reason the algorithm is allowed to exist: the combinatorial condition is also the computational one.
Minimum spanning tree
Kruskal and Prim build a spanning tree of least total weight. Again a polynomial graph algorithm, and again a different object from a Hamiltonian cycle.
3. Decision problems and complexity
Decision problem
A yes/no question about a finite input. “Does \( G \) have an Eulerian circuit?” “Does \( G \) have a Hamiltonian cycle?”
P and NP
Informally: P is the class of decision problems solvable in polynomial time. NP is the class whose yes-instances have polynomial-time checkable certificates. A Hamiltonian cycle, if it exists, is such a certificate: given the cyclic order of vertices, one can check the edges in linear time.
NP-complete
A problem in NP to which every problem in NP reduces in polynomial time. The Hamiltonian cycle problem is NP-complete (Karp, 1972). So is the travelling salesman decision problem. There is no known polynomial algorithm, and none is expected.
The Euler–Hamilton contrast
An Eulerian circuit is polynomial. A Hamiltonian cycle is NP-complete. The definitions are close — every edge versus every vertex — and the computational difference is as sharp as anything in discrete mathematics. That contrast is why Hamiltonian problems are a meeting point of pure mathematics and computer science.
4. Uniquely Hamiltonian graphs, computationally
Counting cycles
Uniquely Hamiltonian means the number of Hamiltonian cycles is exactly one. Counting Hamiltonian cycles is, in general, at least as hard as deciding whether any exist. The mathematical question on this site is not an algorithm for that count. It is which graphs can have count one, and which constructions fail to produce them.
Certificates versus classification
A single Hamiltonian cycle is a certificate of Hamiltonicity. Uniqueness asks that no other certificate of the same kind exists. Proving uniqueness is a different kind of work from finding one cycle.
5. Game theory

Game theory is the other computer science thread, from an undergraduate thesis on traffic regulation rather than from the uniquely Hamiltonian notes.

Players, strategies, payoff
A game in this sense is not a board. It is a collection of players, each with a set of strategies, and a payoff for every profile of choices. Nash equilibrium is a profile from which no player wants to deviate alone. Minimax is the two-player zero-sum case.
Traffic as a game
Intersecting roads can be modelled as competing players. Vehicle density, estimated from video by background subtraction, becomes the input to a Markov framework that chooses green-light durations. The mathematics is game theory and discrete modelling; the implementation is computer vision. Details are on the portfolio.
6. Programming as a tool
Languages
Python, Java, and LaTeX. Code draws figures, checks small examples, and typesets proofs. It is not a substitute for the argument.
What it does not settle
A program that fails to find a second Hamiltonian cycle in a particular graph is evidence, not a classification theorem. The open problems remain mathematical. See Research and Publications.
